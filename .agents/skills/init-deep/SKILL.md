# Init-Deep — Hierarchical Context Generation

The init-deep system generates scoped `AGENTS.md` files throughout the project, providing context that's relevant to each directory. This improves agent performance by loading only the context needed for the current task.

## Why Use Init-Deep?

**Without scoped context:**
- Root AGENTS.md becomes huge and unfocused
- Agents load irrelevant context for simple tasks
- Hard to find conventions for specific areas

**With init-deep:**
- Each directory has its own focused AGENTS.md
- Agents auto-load relevant context
- Conventions are documented where they apply

## Quick Start

### Generate AGENTS.md Files

```bash
# Generate for all key directories
curl -X POST /api/init-deep

# Check status first
curl /api/init-deep/status

# Dry run to preview
curl -X POST /api/init-deep -d '{"dryRun":true}'

# Force overwrite existing files
curl -X POST /api/init-deep -d '{"force":true}'

# Generate for specific path
curl -X POST /api/init-deep -d '{"path":"/path/to/project"}'
```

### Check Generation Status

```bash
curl /api/init-deep/status
```

## Generated AGENTS.md Structure

Each generated file includes:

```markdown
# AGENTS.md — directory-name

## Scope
Brief description of what this directory contains.

## Key Files
| File | Purpose | Exports |
|------|---------|---------|
| file.ts | What it does | exportedFunction |

## Subdirectories
- **subdir/** — See subdir/AGENTS.md

## Conventions
- TypeScript-first
- Use named exports
- Co-locate tests

## Key Dependencies
- Next.js
- Prisma

## Parent Context
See: ../AGENTS.md

---
*Generated by init-deep — 2026-04-04*
```

## TypeScript API

### Generate Context Files

```typescript
import { initDeep, InitDeepOptions } from '@/app/lib/init-deep'

// Generate for default directories
const results = await initDeep()

// With options
const results = await initDeep({
  rootPath: '/path/to/project',
  force: false,        // Don't overwrite existing
  dryRun: false,       // Actually write files
  maxDepth: 5,         // How deep to traverse
  exclude: ['node_modules', '.git'],
  include: ['src', 'lib'] // Only these directories
})

// Results:
// [
//   { path: 'web/app/api', generated: true, skipped: false },
//   { path: 'web/app/lib', generated: false, skipped: true, error: 'Already exists' },
//   { path: 'web/components', generated: true, skipped: false }
// ]
```

### Read Closest Context

```typescript
import { readClosestAgentsMd, hasAgentsMd } from '@/app/lib/init-deep'

// Check if directory has AGENTS.md
if (hasAgentsMd('/path/to/dir')) {
  const context = readClosestAgentsMd('/path/to/dir/file.ts')
  console.log(context) // Content of nearest AGENTS.md
}
```

## Priority Directories

Init-deep automatically processes these directories:

| Directory | Purpose |
|-----------|---------|
| `web/app/api` | API route handlers |
| `web/app/lib` | Shared utilities |
| `web/components` | React components |
| `web/app/hooks` | Custom React hooks |
| `web/app/types` | TypeScript types |
| `agentbot-backend/src` | Express backend |
| `agentbot-backend/src/services` | Backend services |
| `agentbot-backend/src/routes` | Backend routes |
| `skills` | AI skill definitions |

## Best Practices

### 1. Generate After Major Restructuring

```bash
# After reorganizing code
curl -X POST /api/init-deep -d '{"force":true}'
```

### 2. Include Context in Agent Prompts

```typescript
// When starting work in a directory
import { readClosestAgentsMd } from '@/app/lib/init-deep'

export async function startTask(filePath: string) {
  const context = readClosestAgentsMd(filePath)
  
  const prompt = `
${context}

---

Now complete this task:
[your task here]
  `
  
  return await agent.run(prompt)
}
```

### 3. Update When Conventions Change

When you establish new conventions in a directory, regenerate its AGENTS.md:

```bash
# Update specific directory
curl -X POST /api/init-deep -d '{
  "include": ["web/app/api"],
  "force": true
}'
```

### 4. Use Scoped Context for Large Refactors

```typescript
import { initDeep } from '@/app/lib/init-deep'

// Before a large refactor, ensure all context is fresh
await initDeep({ force: true })

// Now each directory has up-to-date context
// for agents working on the refactor
```

## Directory Analysis

Init-deep analyzes each directory to extract:

### File Information
- File names and extensions
- Size and line counts
- Import/export patterns
- JSDoc descriptions

### Inferred Conventions
- Naming patterns (camelCase, PascalCase, kebab-case)
- TypeScript vs JavaScript usage
- Test file locations
- Export patterns

### Dependencies
- External libraries used
- Internal imports
- Framework detection (Next.js, React, etc.)

## Customizing Generation

### Custom Root AGENTS.md

To customize the root AGENTS.md, create a template:

```typescript
// In your init-deep call
import { generateRootAgentsMd } from '@/app/lib/init-deep'

const customRootContent = `
# AGENTS.md — My Project

## Custom Section
Your content here...

${generateProjectStructure()}  // Auto-generated
${generateQuickReference()}    // Auto-generated
`

fs.writeFileSync('AGENTS.md', customRootContent)
```

### Excluding Files

```typescript
await initDeep({
  exclude: [
    'node_modules',
    '.git',
    'dist',
    'coverage',
    '*.test.ts'  // Exclude test files from analysis
  ]
})
```

## Integration with Skills

Skills can use init-deep to understand their environment:

```typescript
// skills/my-skill/index.ts
import { initDeep, hasAgentsMd } from '@/app/lib/init-deep'

export async function initializeSkill() {
  // Ensure context exists
  if (!hasAgentsMd(process.cwd())) {
    await initDeep({
      include: ['.'],
      maxDepth: 2
    })
  }
  
  // Now the skill has context about its environment
  // and can make better decisions
}
```

## Troubleshooting

| Problem | Cause | Solution |
|---------|-------|----------|
| No files generated | Path doesn't exist | Check that directories in `include` exist |
| Outdated context | Files changed since generation | Run with `force: true` |
| Too many files | `maxDepth` too high | Reduce `maxDepth` or use `include` |
| Missing conventions | JSDoc not used | Add JSDoc comments to key exports |
| Empty directories | No source files | Ensure directory has `.ts`/`.tsx` files |
